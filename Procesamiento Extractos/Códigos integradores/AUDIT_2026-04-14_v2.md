## TOP 5 — Prioridades para próxima sesión

### P1 — CRÍTICO: Supervielle clasifica créditos como débitos (`extractor.py:147-156`)

Parser siempre asigna `debit = abs(amount)` y `credit = 0.0`. Reversiones, reembolsos, acreditaciones → inflados como débito.

**Fix:** Usar el segundo número de la línea (saldo) para inferir dirección. Si el saldo aumenta → crédito; si baja → débito. O buscar indicador D/C en la línea.

```python
# Actualmente (MAL):
debit  = abs(amount) if amount > 0 else 0.0
credit = 0.0

# Alternativa: comparar con saldo previo o buscar marcador textual en la línea
```

---

### P2 — CRÍTICO: Santander clasifica créditos como débitos (`extractor.py:590-591`)

Misma falla que Supervielle. Línea: `debit = amount; credit = 0.0` incondicional. El PDF Santander tiene columnas Débito y Crédito separadas (dos montos con `$`).

**Fix:**
```python
# Si la línea tiene 2 montos con $, el primero es débito y el segundo es crédito
if len(moneys) >= 2:
    debit  = parse_money(moneys[0])
    credit = parse_money(moneys[1])
else:
    debit  = parse_money(moneys[0])
    credit = 0.0
```
Requiere validar contra un PDF real con líneas de crédito.

---

### P3 — ALTO: IVA_AMBIG falla siempre al inicio de período (`classifier.py:44-52`)

Cuando `prev_debit == 0` (inicio de mes o después del reset de período), el ratio check salta y retorna `CAT_NONE`. El primer IVA_AMBIG de cada mes queda sin clasificar sistemáticamente.

**Fix:** Agregar heurística de fallback basada en el monto absoluto:
```python
# Fallback adicional cuando prev_debit == 0:
# IVA de comisiones típico: > $5000; IVA de intereses: más pequeño
# O buscar el tipo en la descripción inmediatamente anterior
if debit < 10_000:
    return CAT_IVA_INT  # heurística conservadora
return CAT_IVA_COM
```
O al menos loggear con más detalle (descripción, banco, fecha).

---

### P4 — ALTO: `normalize_date` falla silenciosamente sin log de qué línea causó el problema (`config.py:177-218`)

Cuando la fecha es inválida (ej. 29/02 en año no bisiesto), retorna `""` sin indicar qué string llegó, qué banco lo generó, ni qué período se estaba procesando. El extractor descarta la transacción silenciosamente.

**Fix:** Agregar log en el punto de falla:
```python
# En normalize_date:
try:
    _date(y, mo, d)
except ValueError:
    log.warning(f"Fecha inválida ignorada: '{s}' (year_hint={year_hint})")
    return ""
```

Y en los parsers: también loggear cuando una línea se descarta por fecha vacía:
```python
date = normalize_date(date_str, year)
if not date:
    log.debug(f"  {bank}: línea descartada por fecha inválida: {stripped!r}")
    continue
```

---

### P5 — ALTO: Contaminación cross-file en clasificador cuando mismo banco tiene dos PDFs del mismo período (`classifier.py:65-89`)

El reset de contexto se hace solo en cambio de `period`. Si hay dos PDFs del mismo banco y período, el contexto IVA del primer PDF se heredará al primer IVA_AMBIG del segundo PDF.

**Fix:** Trackear `source_file` además del período:
```python
last_key = None   # (period, source_file)
for txn in transactions:
    current_key = (txn.get('period'), txn.get('source_file'))
    if current_key != last_key:
        if last_key is not None:
            last_cat = CAT_NONE
            prev_debit = 0.0
        last_key = current_key
```

## Contexto para próxima sesión

**Arquitectura:**
- `run_pipeline.py` — orquestador: extraer → clasificar → revisar → confirmar → Excel → verificar
- `config.py` — constantes, paths, logger, `BANK_RULES`, `parse_argentine_number`, `normalize_date`, `make_transaction`
- `extractor.py` — 9 parsers PDF + dispatcher `extract_all`. Cada parser retorna `List[dict]` via `make_transaction()`
- `classifier.py` — `classify_bank()` stateful (last_cat, prev_debit, last_period) + reportes consola
- `verify.py` — compara totales extraídos vs totales oficiales en el PDF (7/9 bancos)

**Patrones clave:**
- `BANK_RULES[banco] = [(CAT, [keywords]), ...]` — primera coincidencia gana. IVA_AMBIG se resuelve post-hoc por contexto o ratio.
- `_CONTEXT_CATS = {CAT_COMISIONES, CAT_IVA_COM, CAT_INTERESES, CAT_IVA_INT}` — solo estas actualizan `last_cat`
- Desambiguación IVA: si `last_cat` apunta a intereses → `CAT_IVA_INT`; a comisiones → `CAT_IVA_COM`; fallback ratio 10.5%/21%
- ICBC: dedup por `(date, description, amount_raw)` para páginas duplicadas en PDF
- verify.py usa lazy `[^$\n]*?` para capturar el PRIMER monto en la línea

**Issues que NO se resolvieron en v1 y siguen abiertos:**
- P2 Santander créditos (C-02)
- P1 Supervielle créditos (C-01)
- Q-05 cat_abbrevs string literals
- RX-01 _NUM_RE permisivo

**Próximo paso natural:** Resolver P1/P2 (créditos Santander/Supervielle) requiere analizar un PDF con créditos reales. Si el mes actual no tiene créditos, hacerlo en forma preventiva analizando el formato del PDF.
